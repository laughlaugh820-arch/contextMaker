# contextMaker 実装計画

目標: 青空文庫の作品をリポジトリに保存し、そこから物語の構成・比喩表現・文章技法を抽出して、
オリジナルの物語を生成できる仕組みを作る。

パイプラインは 4 段。各段は独立したスクリプトで、前段の出力ファイルだけを入力にする。

```
library/   ──(1 済)──  tools/aozora.py         取得・整形
analysis/  ──(2)────  tools/analyze.py        作品ごとの抽出結果 JSON
context/   ──(3)────  tools/build_context.py  LLM に渡すための Markdown 群
stories/   ──(4)────  tools/story.py          プロンプト合成 + Claude API で生成
```

## 2. 抽出 `tools/analyze.py`（未着手）

入力: `library/*/*/plain.txt` と `meta.json`。出力: `analysis/<person_id>/<work_id>.json`。
標準ライブラリのみ。形態素解析器は使わない（環境に依存させない）。

抽出項目:

- **文分割**: 「。」「！」「？」で区切る。直後の「」『』の閉じ括弧は前の文に付ける。
  会話文（行頭が「 で始まる段落）と地の文を区別する。
- **基本統計**: 文数、段落数、文長の平均・中央値・標準偏差・最大、会話率（会話段落の文字数比）、
  漢字率、読点の1文あたり平均、ダッシュ「――」と三点リーダ「……」の出現率。
- **章構成**: 短い行（10文字以下）で漢数字・算用数字・「上中下」・「一、」のような見出しを検出し、
  各章の文字数を並べる。
- **緊張曲線**: 本文を 10 等分し、区間ごとに会話率・平均文長・感嘆/疑問符密度・
  ダッシュ密度を出す。構成のプロファイルとして使う。
- **比喩**: 直喩マーカーを含む文を抜き出す。
  「〜のように」「〜のような」「〜のごとく」「〜ごとし」「〜さながら」「〜あたかも」「〜まるで」
  「〜みたいな」「〜に似た」「〜と見紛う」。文とマーカー種別、位置（0〜1）を記録。
- **オノマトペ**: ABAB 型の反復（ざあざあ、ちらちら）と促音・撥音を含む短い仮名語を検出。
- **書き出し・結び**: 冒頭 3 文、末尾 3 文。
- **反復・畳みかけ**: 同じ語句で始まる連続文、同一文の反復。
- **語彙の癖**: 出現頻度が高い 2〜4 文字の語（形態素解析なしで n-gram + 簡易フィルタ）。
  ただし精度は低いので参考値扱い。

## 3. コンテキスト生成 `tools/build_context.py`（未着手）

入力: `analysis/`。出力: `context/` 以下の Markdown。LLM のコンテキストにそのまま貼れる粒度。

- `context/README.md` — 索引
- `context/works/<author>_<title>.md` — 作品カード: 統計、章構成、緊張曲線（表）、書き出し・結び、比喩例 10 件
- `context/authors/<author>.md` — 作家プロファイル: 全作品の統計を平均し、文体の特徴を数値と例文で示す
- `context/techniques/similes.md` — 比喩カタログ。作家別、マーカー種別で整理
- `context/techniques/openings.md`, `closings.md` — 書き出し・結びの一覧
- `context/techniques/onomatopoeia.md`
- `context/techniques/structure.md` — 緊張曲線の型（会話が後半で増える型、前半に集中する型…）を作品ごとに並べる
- `context/guide/story_craft.md` — **手書き**の創作ガイド。抽出結果を根拠にして、
  構成の型、比喩の作り方、書き出しの型、文長の緩急、会話と地の文の配分、などを
  実例つきで整理する。生成物のうち一番価値があるのはこれ。機械生成ではなく読んで書く。

## 4. 物語生成 `tools/story.py`（未着手）

- `compose --theme "…" [--author 芥川龍之介] [--length 4000] [--structure <作品ID>] [--out prompt.md]`
  `context/` から該当する作家プロファイル、比喩例（ランダム N 件）、参照する構成の緊張曲線、
  創作ガイドを組み合わせてプロンプトを組み立てる。API を使わずプロンプトだけ出力できる。
- `generate` は `compose` の結果を Claude API に投げ、`stories/<日付>_<slug>.md` に
  使ったプロンプトと生成物を並べて保存する。`ANTHROPIC_API_KEY` が必要。
  **API 呼び出しのコードを書く前に `claude-api` スキルを読むこと**（モデルID・SDK の使い方が変わる）。
- 生成物は「青空文庫の作品の模倣」ではなく「抽出した技法を使ったオリジナル」になるよう、
  プロンプトで固有名詞・筋の流用を禁じる。

## 5. 仕上げ

通しで `fetch → analyze → build-context → compose` を実行し、README にワークフローを書く。
`stories/` に `compose` の出力サンプル（プロンプト）を 1 つ置く。API キーがあれば `generate` も試す。

## 決めごと

- Python 3.9+、標準ライブラリのみ（生成の anthropic SDK だけ例外、未インストールなら compose のみ動く）
- 各ツールは冪等。再実行しても同じ出力になる
- `library/` `analysis/` `context/` はコミットする。再現できるが、読む側が手元で走らせなくて済むように
